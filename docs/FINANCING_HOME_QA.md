# Проверка «Финансирования бизнеса»

Первоначальная проверка: 24 октября 2026. Актуальные результаты после ревью ниже.

## Реализованное поведение

- «Главная» активна и открывает /home. «Мои заявки» остаются на /.
- Основной блок, выбранная заявка и Альфи используют общую модель следующего действия.
- Запрос банка, подпись и предложение приоритетнее черновика и ожидания банка.
- Фильтры не меняют выбранную заявку. Завершение выбранной заявки убирает команды.
- Черновики отделены от отправленных заявок. Отсутствующие данные не заменяются выдуманными.
- Сводка компании использует известные данные сессии, состояние источников получает через API.
- Серверный список и карточка ограничены компанией сессии. Контекст АРМ доступен сотруднику.
- Новые компании, показатели, заявки и seed-данные не добавлялись. Фикстуры новых unit-тестов существуют только в памяти тестового процесса.

## Первоначальная автоматическая проверка

На macOS, Node 24, pnpm 11.25.0 и установленном uv:

- pnpm lint: успешно. ESLint выводит существующее сообщение об отсутствии корневого pages, код выхода 0.
- pnpm check-types: успешно для всех восьми задач.
- pnpm boundaries: успешно.
- pnpm build: успешно, клиентский маршрут /home включён в сборку.
- pnpm --filter client test: 15 успешно, пропусков нет.
- pnpm --filter api test: 20 успешно, 27 существующих интеграционных тестов пропущены без TEST_DATABASE_URL.

Новые тесты покрывают приоритеты, терминальные состояния, блокировку, неполный запрос,
подготовку договора, выдачу, ручной фокус, удаление выбранной заявки, стабильную сортировку,
черновики, серверную принадлежность и наличие session guards.

## Проверка на работающих сервисах

Выполнена на уже существующей локальной базе, без запуска db:seed:

- каждая из трёх существующих компаний получила только свою заявку;
- чтение чужой заявки по ID возвращает 404;
- анонимный список, карточка, задача и контекст возвращают 401;
- клиент не может читать банковский контекст;
- сотруднику доступны очередь из трёх существующих заявок и контекст;
- в браузере смена компании убрала предыдущую заявку и финансовые показатели;
- фильтр без результатов и кнопка «Показать все» работают;
- ручной выбор и «К ближайшему действию» работают;
- переходы в заявку, компанию и подбор продукта открывают существующие экраны.

Без новых данных не воспроизводились живые сценарии запроса, предложения и подписания.
Их маршруты и классификация проверены unit-тестами; полный новый кредитный цикл
в этом изменении не заявляется как пройденный.

## Визуальная проверка и antislop after

- PASS, композиция: одно главное действие, одна дорожная карта; контекст компании вторичен.
- PASS, данные: показатели получены из существующих API/сессии, новых демонстрационных значений нет.
- PASS, адаптивность: на 375, 768 и 1440 px ширина документа равна ширине viewport, горизонтального переполнения нет.
- PASS, темы: светлая и тёмная проверены в браузере.
- PASS, клавиатура: Tab переводит фокус между фильтрами, видимый контур 2 px; DOM-порядок совпадает с визуальным.
- PASS, контраст: светлая тема: основной текст 18.58:1, вторичный 6.38:1, предупреждение 4.75:1. Тёмная: 14.05:1, 6.85:1 и 10.06:1.
- PASS, стиль: сохранены Mantine, Golos и токены темы. Нет новых декоративных изображений и бесконечных анимаций.
- PASS, ограничения: нет выдуманных вероятностей, сроков и кредитных лимитов.

Причины композиции: крупный блок выделяет действие; строки позволяют сравнить заявки;
переиспользование темы сохраняет целостность; справка компании показывает источник цифр.
ENERGY 1 / RHYTHM 2 / MOTION 1.

Состояния ошибки источников, загрузки и неполных данных реализованы, но не все
принудительно воспроизводились в браузере. Проверка очень длинных наименований
не проводилась подменой пользовательских данных.

## Исправления ревью, 25 октября 2026

Ветка перенесена на dev 595989f. Сохранены добавленные командой дорожная карта,
срочный запрос, причины отмены и сервис доступа клиентских отчётов.

1. Словарь финансирования выбирает полноценный ru/en-набор по Locale.
   Тесты проверяют равенство ключей, различие переводов, динамические подписи и fallback.
   Сама страница по умолчанию остаётся русской согласно конфигурации приложения.
2. ИНН ограничивает параметризованный SQL до загрузки строк. Банковская очередь
   сохраняет чтение без клиентского ограничения. Такой же фильтр применён к
   списку существующего ClientApplicationScopeService для клиентских отчётов.
3. Карточка использует строку, уже полученную под блокировкой для проверки срока
   оффера. Повторного SELECT заявки после assertAccess нет. При этом видимые
   клиенту комментарии и обработка истечения оффера сохраняются.
4. Swagger описывает 401 для guarded-маршрутов, 403 для создания от чужой компании,
   404 для отсутствующей или недоступной заявки/задачи. Реальные ответы проверены
   в /docs-json; чужая карточка не объявляется как 403, поскольку возвращает 404.
5. needs_client без незакрытого запроса явно возвращает invalid.
6. При проверке FUNDED обнаружена и исправлена подпись «Этап 7 из 6»:
   завершённый путь подписан «Все этапы пройдены». В фокусе отклонённой заявки
   не показываются будущие этапы.

Повторные проверки:
