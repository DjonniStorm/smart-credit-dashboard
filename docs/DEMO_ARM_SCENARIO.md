# Демо-сквозняк банковского АРМ

Сценарий рассчитан на API-режим backoffice. Данные синтетические и хранятся в PostgreSQL.

## Запуск

```bash
pnpm --filter api db:seed
pnpm --filter backoffice dev
```

Открыть [http://127.0.0.1:3001/login](http://127.0.0.1:3001/login), выбрать «Аналитик Демо 1» и войти.

Повторный запуск seed не создаёт дубликаты. Сброс состояния выполняется через базу данных перед новым сценарием.

## Основной путь: заявка → проверка → scoring

1. В очереди открыть одну из трёх seed-заявок.
2. Проверить компанию и карточку заявки.
3. Запустить проверку и дождаться polling job.
4. Убедиться, что scoring и три индекса пришли из API.
5. Проверить, что действия изменения заявки отключены до появления команд API.

## Состояния в seed

| Заявка | Что проверяет |
| --- | --- |
| SC-DEMO-001 | стабильный профиль и оборотный кредит |
| SC-DEMO-002 | оборудование и налоговый долг |
| SC-DEMO-003 | просрочка в БКИ и ручное внимание |

## Критерии готового демо

- один сквозной путь проходит без ручного редактирования браузера;
- повторный seed не меняет количество заявок и продуктов;
- job сохраняется после перезапуска API;
- неподключённые команды не подменяются локальным состоянием.
