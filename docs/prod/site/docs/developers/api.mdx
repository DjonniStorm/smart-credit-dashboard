# API

Client Web и Backoffice Web меняют заявку через HTTP API. Сервер проверяет сессию и полномочия, валидирует команду, применяет допустимый переход и возвращает актуальное состояние. Клиентские интерфейсы не меняют статус локально в обход ответа API.

## Контракт и документация

OpenAPI-документ строится из серверных контроллеров и схем. При локальном запуске Swagger UI доступен по адресу [`http://localhost:4000/docs`](http://localhost:4000/docs). Для развернутого контура используйте [Swagger API](https://api.sales.eegov.net/docs). Эти ссылки дополняют друг друга: первая проверяет локальный запуск, вторая показывает опубликованный API.

АРМ использует сессию сотрудника. Действия с заявкой передают команду и ключ идемпотентности; сервер проверяет допустимость перехода и сохраняет его вместе с записью истории.

Этот сайт не зеркалирует OpenAPI-схему. Для актуальных путей, параметров и ответов используйте Swagger запущенной версии API.

## Коллекция запросов

[Коллекция Postman для профиля и проверок компании](https://github.com/DjonniStorm/smart-credit-dashboard/blob/dev/docs/api-collection/company-profile.postman_collection.json) содержит последовательность запросов с входом через демо-профиль, сохранением cookie, согласием БКИ и синтетической проверкой источников. Импортируйте JSON, задайте `baseUrl` и запускайте запросы по порядку в Collection Runner. Cookie jar Postman должен быть включён. Это коллекция профиля компании, не полный экспорт всех маршрутов Swagger.

Связи таблиц описаны в [модели данных](/developers/data-model), а последовательность ручной проверки — в [сценариях](/developers/verification-scenarios).
