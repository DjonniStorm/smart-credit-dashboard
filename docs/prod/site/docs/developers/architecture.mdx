# Архитектура

Система состоит из двух интерфейсов, API и отдельного сервиса scoring. Интерфейсы обращаются к серверной части по HTTP, а API владеет состоянием заявки и хранением данных.

```text
Кабинет предпринимателя ── HTTP ──┐
                                  ├── API ── PostgreSQL
Банковское АРМ ────────── HTTP ──┘    ├── фоновые задачи и проверки
                                      └── scoring
```

## Границы компонентов

- **Кабинет предпринимателя** собирает данные, документы и ответы клиента. Источник состояния заявки находится на стороне API.
- **Банковское АРМ** показывает очередь и отправляет действия сотрудника.
- **API** проверяет доступ, выполняет допустимые переходы, сохраняет данные и историю действий.
- **Scoring** рассчитывает результат и объяснение. Сервис не меняет состояние заявки самостоятельно.
- **PostgreSQL** хранит заявки и связанные с ними сведения.

В демонстрационном окружении часть внешних проверок и переходов смоделирована. Эта схема описывает границы компонентов проекта, а не SLA размещённого сервиса.
