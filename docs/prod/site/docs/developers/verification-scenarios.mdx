# Сценарии проверки

Запустите сервисы по [инструкции локальной разработки](/developers/local-development) и выполните `pnpm --filter api db:seed`. Для HTTP-запросов используйте [локальный Swagger](http://localhost:4000/docs) или [коллекцию Postman](/developers/api). Сценарии ниже проверяют реализованные переходы; возможный полный путь на диаграмме включает также логические этапы, которые API не хранит отдельно.

## 1. Подача и расчёт

1. Откройте `http://localhost:3000`, выберите компанию и заполните новую заявку.
2. Отправьте её один раз; запишите номер заявки.
3. Откройте заявку в `http://localhost:3001` и дождитесь результата проверки.
4. Сверьте номер, продукт, сумму и статус в обоих интерфейсах. Новая заявка начинается в `in_review` (`UNDER_REVIEW` в публичной модели), а scoring выполняется через задание в `scoring_jobs`.

## 2. Расхождение профиля и ответ клиента

1. Выберите демо-компанию, у которой отображено расхождение регистрационных сведений между источниками.
2. Отправьте заявку и дождитесь scoring. Если нет открытого запроса и заявка остаётся на рассмотрении, система создаёт запрос с перечнем подтверждений и причинами расхождения.
3. В кабинете клиента откройте запрос и отправьте ответ.
4. В АРМ проверьте ответ и продолжите рассмотрение. Проверьте, что история заявки сохранила события действий.

Автоматический запрос относится только к расхождениям профиля компании. Для остальных случаев сотрудник использует ручной запрос. Сценарий зависит от данных выбранной демо-компании и поэтому не должен считаться пройденным без видимого расхождения.

## 3. Повтор команды

1. В Swagger выберите команду изменения заявки, требующую ключ идемпотентности.
2. Отправьте её с тем же ключом дважды, сохранив одинаковое тело запроса и авторизованную сессию.
3. Проверьте, что повтор не создал второй переход или второе действие в истории.

Контракты конкретной команды и заголовки смотрите в Swagger запущенной версии. Автоматические проверки API запускаются командой `pnpm --filter api test` из корня репозитория; они дополняют ручной маршрут, но не заменяют проверку интерфейсов.
