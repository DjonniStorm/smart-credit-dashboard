# API заявки и фоновой scoring job

Контракт workflow находится в `@repo/contracts/workflow`.

## Сквозной сценарий

1. `POST /v1/applications` принимает заявку и обязательный `idempotencyKey`.
2. API создаёт заявку со статусом `in_review`, ставит job проверки в очередь и
   возвращает `application` вместе с `checkJob.id`.
3. `GET /v1/jobs/:id` используется для polling. Состояния: `queued`, `running`,
   `succeeded`, `failed`.
4. После успеха результат baseline scoring записывается в заявку и доступен через
   `GET /v1/applications/:id`.
5. `POST /v1/applications/:id/checks` запускает повторную проверку. Повтор с
   тем же `idempotencyKey` возвращает ту же job и не вызывает scoring повторно.

Idempotency scope: ключ создания уникален для операции создания, ключ проверки
уникален внутри заявки. Заявка, job и ключ создаются одной транзакцией; ключ
вставляется первым, поэтому параллельные запросы с одним ключом получают одну
заявку. Идентификаторы заявок и job — UUID, номер заявки `SC-<n>` выдаёт sequence в базе.

Job обрабатывает Postgres-воркер (`FOR UPDATE SKIP LOCKED`). Ошибка скоринга или
записи уводит job в retry с задержкой (`next_attempt_at`), после трёх попыток job
получает `failed`. Job в `running` дольше `JOB_LEASE_MS` (по умолчанию 60 с)
возвращается в очередь или переходит в `failed`, если попытки закончились.

Ошибки источников и scoring не меняют scoring заявки: сообщение (без сырых ответов)
сохраняется в `error`, а по неудачной попытке job уходит в retry (см. выше) и
становится `failed` только после трёх попыток. Статус проверки по каждому источнику
(`egrul`, `bki`, `fns`, `scoring`) пишется в `source_checks` в той же транзакции,
что и итог job: при успехе по строке на источник со статусом `ok`, при сбое строка
с источником, который отказал (`sources` или `scoring`), статусом `failed` и
сообщением. Сырые ответы внешних систем не сохраняются.

Итог попытки применяется, только пока job принадлежит этой попытке
(`status='running'` и тот же `attempts`): поздний ответ воркера, чью job уже
подобрал recovery, ничего не перезаписывает. Recovery пишет событие
`scoring_failed` с причиной.
